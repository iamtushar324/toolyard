The problem

Five agents, five config files,
zero oversight.

Every coding agent reinvents MCP configuration, approval UX, and audit logging — or worse, ships with --dangerously-skip-permissions. Your GitHub token lives in four JSON files. Nobody remembers which agent deleted that branch.

The fix

One control plane,
between agents and the world.

Point every agent at toolyard instead. Upstream MCP servers get configured once. Every call flows through the same policy engine, waits for the same approval tap, and lands in the same audit log — no matter which agent made it.

Capabilities

Mission control for your agents

Approve from your pocket

Writes pause for a human. A push notification hits your phone with the agent's reason — Allow or Deny in one tap, signed Ed25519 decision tokens under the hood.

A policy engine that learns

Explicit rules, intent categories, and read-heuristics decide allow / approve / deny. Auto-approval learns your taps — with cool-offs after denials and a hard veto on destructive tools.

One audit trail

Every call from every agent in one append-only log — who, what, why, and what happened — streamed live to the dashboard over SSE. Anomaly scoring flags what doesn't fit.

Shared memory

memory.set in Claude Code, memory.get in Codex. A built-in scoped KV store every connected agent can reach — through the same approval policy as everything else.

A personal data lake

ClickHouse-backed warehouse with read tools agents can query and approve-gated mutation tools. Manifest-driven dashboards: a SQL file becomes a chart.

Single binary, zero SaaS

Go + SQLite + a PWA dashboard. Runs on a laptop or a $5 VPS behind systemd sandboxing. Your tokens, your audit log, your hardware — nothing phones home.

Every call carries a reason

toolyard wraps every upstream tool schema with a required _reason field. Agents must say why — in words a human reviews on the approval card and in the audit log.

Approvals don't block agents

A write that needs your tap returns a deferred envelope instead of hanging the connection. The agent moves on and polls tools.poll_approval; you decide on your own time.

github.create_issue → deferred 
// agent calls github.create_issue with its reason
{
  "title": "Flaky test in oauth refresher",
  "_reason": "User asked me to file the bug we
              just reproduced in CI run #4188"
}

// toolyard holds the write and answers immediately
{
  "_meta": { "toolyard": {
    "deferred": true,
    "approval_id": "ap_7f3ac21d",
    "expires_at": "2026-06-11T12:40:00Z"
  }}
}

// you tap Allow on your phone → agent polls the result
tools.poll_approval { "approval_id": "ap_7f3ac21d" }

Get started

Running in under a minute

$ 
==> resolving latest release
==> verifying checksum
toolyard installed: /usr/local/bin/toolyard

$ toolyard serve -addr :8787 -data ~/.toolyard
open http://localhost:8787 — create your admin account,
enroll your agents, add upstreams.
$ git clone https://github.com/iamtushar324/toolyard
$ cd toolyard
$ docker compose -f deploy/docker-compose.yml up -d
# dashboard on http://localhost:8787, data in the
# toolyard-data volume
$ git clone https://github.com/iamtushar324/toolyard
$ cd toolyard
$ sudo ./deploy/install.sh
# builds from source, installs a sandboxed systemd unit,
# and (with docker present) brings up ClickHouse + Grafana
# for the personal data lake
$ git clone https://github.com/iamtushar324/toolyard
$ cd toolyard
$ make build          # needs Go 1.25+ (CGO)
$ ./gateway-darwin serve -addr :8787 -data ~/.toolyard

Then point your agents at it:

claude mcp add toolyard --transport http http://localhost:8787/mcp
